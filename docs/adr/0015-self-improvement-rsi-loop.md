# ADR-0015: Self-improvement and the RSI loop

Status: accepted · Date: 2026-10-22

## Context
The tool should get better from its own run outcomes and accept feature requests, but an unattended
agent that edits an application which submits job applications is a safety risk. Humans must stay the
gate for anything that changes behaviour in code.

## Decision
1. **`request_feature(description, kind?)`** classifies (platform_adapter, control, config, new_tool, bug;
   deterministic keyword rules, overridable), builds a compact context pack (module map, Protocols, a sibling
   template, related ADRs, matching failure clusters), and writes a proposal (spec, files, test plan, risk, ADR
   draft) to `data_dir/proposals/<id>/`. A configurable CODER (`improve.coder`) then acts:
   `none` (proposal only, default), `client` (returns a `client_task`), `claude_code` (headless `claude -p`,
   restricted `--allowedTools`), `aider` (model resolved from the router's tier/provider config).
2. **Rails owned by the harness, not the backend**: fresh git worktree on `auto/<id>-<slug>` from
   `<remote>/<base>`; changed paths must match `allowed_paths` and avoid `forbidden_paths` (secrets, lockfile,
   CI, pyproject, config/profile); added lines are scanned for secrets; lint + tests must pass before commit;
   push only the auto branch; `gh pr create` with the proposal and "Generated by job-apply-mcp
   self-improvement; requires human review". It never merges and never pushes to the base branch.
   All commands go through a `CommandRunner` so tests use fakes.
3. **Risk tiers**: T0 playbook notes (mechanics only, scrubbed of emails/phones/URLs, auto-written);
   T1 config / profile-pattern changes (auto-applied only if `improve.auto_apply_low_risk=true`, default
   false; written to `data_dir/improve/overlay.json`, recorded in `applied.jsonl` with before/after values and
   the cluster count before, later compared with post-change counts in `improvement_report`); T2 code (always a
   PR via request_feature). Any request touching CAPTCHA, stop phrases, dry_run, credentials is risk `high`.
4. **RSI analyzer** reads the store's `applications.db` events table (read-only), control's
   `control_audit.jsonl` (violations become gate reasons) and an optional `runs.jsonl` (field labels, stage
   timings, LLM tiers, unresolved questions). It clusters by platform, field label, normalized error text,
   gate reason and LLM tier, ranks by count x weight, and `improvement_report()` returns the compact list.
5. **Playbook memory**: `data_dir/playbooks/<platform>.json` (+ `.md`), read via `PlaybookStore.lessons()`
   by adapters/the browser driver; updated by the analyzer.

## Consequences
Overlay consumers (config loader, apply engine) must read `overlay.json`; wiring is deferred to those components.
Keyword classification is crude but predictable. Rollback is `git revert` for PRs and deleting an id from
`overlay.json` for T1 changes.

## Verify / revert
`uv run pytest tests/test_improve.py -q`. Revert: `git revert <squash sha>`; the feature is inert unless
`improve.coder` is set, and T1 auto-apply is off by default.
